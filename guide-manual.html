사용 가이드

현재 구현된 화면의 사용 순서입니다. 이 문서는 작업 데이터와 API 설정을 읽거나 변경하지 않습니다. 디자인 시스템 링크 활성화를 위해 로그인 인증만 확인합니다.

01 — 시작과 화면 조작

빈 캔버스에서 시작합니다.

이미지를 놓고 생각을 연결한 뒤, 그 맥락을 AI에게 전달할 글쓰기 가이드로 만듭니다. 처음에는 예시 노드가 없습니다. 로그인 후 빈 캔버스 중앙에 이미지 드래그 안내가 표시되고, 노드가 생기면 사라집니다. 저장된 작업이 있으면 같은 브라우저와 경로에서 불러옵니다.

캔버스에서 시작하기
별도의 모드 버튼 없이 사용하는 기본 조작
동작결과
노드 또는 링크 클릭대상을 선택하고 그 옆에 해석 편집창을 엽니다.
노드 드래그해당 노드의 위치를 바꿉니다.
빈 공간 드래그 / 마우스 휠캔버스 이동 / 확대·축소
빈 공간 클릭노드·링크 선택을 해제하고 해석 편집창을 닫습니다.
Shift+클릭여러 항목의 선택을 조정합니다. Shift를 누른 동안에는 노드를 이동하지 않습니다.
전체 보기노드들이 보이도록 화면을 맞춥니다.

글쓰기 패널과 온톨로지 구조는 각각의 닫기 버튼으로 닫습니다. 빈 공간 클릭이나 Esc 키로 글쓰기 패널이 닫히지 않습니다.

02 — 이미지와 노드

이미지를 놓으면 노드가 됩니다.

  1. 빈 캔버스에 이미지를 드래그앤드롭합니다.

    썸네일 노드가 즉시 생성됩니다. PNG·JPEG·WebP, 이미지당 최대 2MB를 지원합니다.

  2. 노드 해석에서 출처와 해석을 적습니다.

    이미지 출처(최대 500자)와 해석(최대 200자)을 입력하고 저장합니다.

  3. 노드를 다시 클릭해 수정합니다.

    저장된 출처나 해석이 있으면 버튼이 수정으로 표시됩니다.

기존 노드 위에 새 이미지를 놓으면 원래 이미지는 유지되고, 겹치지 않는 위치에 새 노드와 기존 노드에서 새 노드로 향하는 연결이 생성됩니다. 새 노드 내용을 먼저 입력하고, 관계 해석은 나중에 링크를 클릭해 작성합니다.

수정과 삭제

로컬 모드에서는 브라우저 식별자, 협업 모드에서는 로그인 계정 ID를 기준으로 노드 출처·해석 수정과 삭제를 허용합니다. 생성자를 확인할 수 없는 기존 노드는 읽기 전용입니다. 표시 이름을 바꿔도 소유권은 바뀌지 않습니다.

선택 후 상단 삭제를 실행합니다. 노드를 지우면 붙어 있는 링크도 삭제되며, 연결된 다른 노드는 남습니다. 로컬 모드에서는 삭제 되돌리기를 사용할 수 있습니다. 협업 모드는 삭제 전 확인을 거치며 되돌리기를 지원하지 않습니다. Delete·Backspace 단축키는 캔버스에 포커스가 있을 때만 적용하며, 글쓰기 패널이 열려 있으면 적용하지 않습니다.

03 — 연결과 관계 해석

한 연결에 여러 해석을 쌓습니다.

  1. 기존 노드끼리는 연결 만들기를 누릅니다.

    시작 노드와 도착 노드를 차례로 클릭합니다. 연결에는 방향이 있습니다.

  2. 관계 계열과 하위 관계를 고릅니다.

    링크 옆 편집창에서 관계의 정의를 적습니다. 다른 해석 추가로 여러 해석을 작성한 뒤 저장할 수 있습니다.

  3. 저장된 해석에 의견을 남깁니다.

    의견은 등록 순서대로 표시됩니다. 각 의견에 동의 또는 비토를 표시하고, 자신의 반응을 바꾸거나 취소할 수 있습니다.

의견 삭제는 해당 의견과 그에 달린 동의·비토를 삭제합니다. 관계 해석이나 노드까지 지우지는 않습니다. 링크 자체를 삭제하려면 캔버스에서 링크를 선택한 뒤 상단 삭제를 사용합니다.

관계 이름이 ‘원인’이더라도 작성자가 제안한 해석입니다. 온톨로지가 인과관계를 사실로 판정한 것은 아닙니다.

관계를 이해하고 선택하기

먼저 “A의 어떤 내용이 B의 어떤 내용과 어떻게 연결되는가?”를 한 문장으로 적어 보세요. 그 문장에 맞는 관계를 선택하고, 적용 범위와 판단 이유를 관계의 정의에 남깁니다.

1. 화살표와 관계의 의미를 구분하세요

A → B에서 A는 시작 노드, B는 도착 노드입니다. 화살표 자체는 원인·시간 순서·찬성을 뜻하지 않습니다. 아래 예시는 읽는 방식을 설명하기 위한 예시이며, 실제 의미는 참여자가 작성한 관계의 정의와 함께 읽습니다.

원인과 결과 예시는 모두 “A로 인해 B가 나타난다”는 같은 방향을 사용합니다. 원인은 A의 작용에, 결과는 B의 변화에 초점을 둡니다. 결과를 선택한다고 화살표가 반전되지는 않습니다. “A가 B의 결과”라는 뜻이라면 그 문장을 정의에 분명히 적거나 B → A로 방향을 바꾼 뒤 정의를 다시 확인하세요.

2. 논리적 관계: 설명과 비교를 구성할 때

논리적 관계 8가지
관계선택 기준A → B 예시와 정의
원인선택 기준A가 B를 일으키거나 변화에 기여한다고 해석할 때 선택합니다.A → B 예시와 정의A 자동화 도입 → B 반복 업무 감소: “자동화가 반복 업무를 줄이는 데 기여했다고 해석한다.”
결과선택 기준A로 인해 나타난 B의 변화나 산출에 초점을 둘 때 선택합니다. 이 예시에서는 A가 원인, B가 결과입니다.A → B 예시와 정의A 자동화 도입 → B 재교육 수요 증가: “자동화 도입의 결과로 재교육 수요가 늘었다고 해석한다.”
전제선택 기준B의 논의가 성립하려면 먼저 가정하거나 충족해야 하는 조건 A를 제시할 때 선택합니다.A → B 예시와 정의A 데이터 품질 확보 → B AI 분석 활용: “데이터의 정확성이 확보된다는 조건에서 분석 결과를 활용한다.”
근거선택 기준A의 자료·관찰·사례가 B의 주장을 뒷받침할 때 선택합니다. 근거를 제시하는 것과 원인을 주장하는 것은 다릅니다.A → B 예시와 정의A 이용자 설문 → B 교육 필요성 주장: “설문에서 확인한 어려움을 교육이 필요하다는 주장의 근거로 제시한다.”
상호 보완선택 기준A와 B가 서로 부족한 부분을 채워 함께 설명하거나 활용할 수 있을 때 선택합니다.A → B 예시와 정의A 통계 자료 → B 인터뷰: “통계가 변화의 규모를, 인터뷰가 그 경험을 설명한다.”
대조선택 기준같은 비교 기준에서 A와 B의 차이를 드러낼 때 선택합니다. 서로 반대하거나 충돌한다는 뜻일 필요는 없습니다.A → B 예시와 정의A 빠른 도입 전략 → B 단계적 도입 전략: “같은 목표를 두고 도입 속도와 위험 관리 방식을 비교한다.”
유사선택 기준A와 B가 어떤 특징이나 구조를 공유하는지 설명할 때 선택합니다. 닮았다는 것만으로 원인이나 결론까지 같아지지는 않습니다.A → B 예시와 정의A 사례 → B 사례: “두 사례 모두 이용자 교육이 부족했다는 점에서 유사하다.”
부분과 전체선택 기준한 내용이 다른 내용의 구성 요소임을 설명할 때 선택합니다. 어느 쪽이 부분이고 전체인지 정의에 적습니다.A → B 예시와 정의A 개인정보 보호 정책 → B AI 거버넌스: “A는 B를 구성하는 정책 중 하나다.”

전제는 논의의 조건이고, 근거는 주장을 뒷받침하는 자료입니다. 대조는 차이를 비교하는 것이고, 반대는 어떤 주장이나 제안을 받아들이지 않는 입장입니다.

3. 정치적·입장 관계: 입장과 행동을 설명할 때

이 계열은 정당이나 정치 기사에만 쓰는 분류가 아닙니다. 사람·집단·주장이 서로 어떤 입장을 취하거나 어떤 행동을 함께 하는지 설명할 때 사용합니다.

정치적·입장 관계 6가지
관계선택 기준A → B 예시와 정의
지지선택 기준A의 인물·집단·입장이 B의 제안이나 행동을 뒷받침할 때 선택합니다.A → B 예시와 정의A 사용자 단체 → B 교육 확대 제안: “A는 B의 제안이 실행되도록 지지한다.”
반대선택 기준A의 입장이 B의 주장·제안에 이의를 제기하거나 수용하지 않을 때 선택합니다.A → B 예시와 정의A 단체 → B 전면 도입안: “A는 비용 문제를 이유로 B의 도입안에 반대한다.”
동의선택 기준A와 B가 특정 판단이나 주장에 대해 같은 입장임을 설명할 때 선택합니다. 행동에 대한 지원까지 뜻하지는 않습니다.A → B 예시와 정의A 전문가 의견 → B 연구 결론: “A는 B의 위험 평가에 동의한다.”
갈등선택 기준A와 B의 목표·이익·요구가 충돌하는 상황을 설명할 때 선택합니다.A → B 예시와 정의A 비용 절감 목표 → B 고용 안정 요구: “두 요구가 인력 운영 방식을 두고 충돌한다.”
협력선택 기준A와 B가 공동 목표를 위해 역할이나 자원을 함께 사용하는 상황에 선택합니다.A → B 예시와 정의A 대학 → B 기업: “대학은 교육을, 기업은 실습 기회를 제공해 공동으로 인력을 양성한다.”
대안선택 기준A를 B 대신 고려할 수 있는 방안으로 제시할 때 선택합니다. 무엇을 대체하는지 정의에 적습니다.A → B 예시와 정의A 단계적 시범 도입 → B 즉시 전면 도입: “A를 B의 비용과 위험을 줄이기 위한 대안으로 제안한다.”

4. 관계의 정의를 구체적으로 적으세요

“A의 [내용]은 B의 [내용]과 [관계]에 있다. 그 이유는 [자료 또는 판단]이며, [적용 범위·불확실성]이 있다.”처럼 작성할 수 있습니다. 관계 이름을 반복하기보다 누가 무엇을 어떻게 연결해 해석했는지 적으세요.

예: “A의 설문에서 교육 부족을 호소한 응답을 B의 교육 확대 제안에 대한 근거로 본다. 한 기관의 설문이므로 전체 산업으로 일반화하지 않는다.”

유사·대조·상호 보완처럼 양쪽을 함께 비교하는 관계도 시스템이 역방향 연결을 자동으로 만들지는 않습니다. 비교 기준을 정의에 적고, 반대 방향에서 별도의 의미를 기록할 필요가 있을 때만 역방향 연결과 해석을 추가하세요.

5. 관계, 의견, 반응을 구분하세요

관계 유형의 지지·동의는 A와 B 사이의 의미입니다. 의견의 지지함·지지하지 않음·판단 유보는 그 관계 해석에 대한 참여자의 입장입니다. 의견에 누르는 동의·비토는 해당 의견에 대한 반응입니다. 반응 수로 해석의 사실성이나 채택 여부를 확정하지 않습니다.

한 연결을 서로 다르게 읽는다면 다른 해석 추가로 각각의 정의를 남길 수 있습니다. AI는 저장된 관계 이름·정의·작성자·의견을 함께 참고하므로, 의미가 불분명한 관계를 추측하게 하기보다 정의를 구체적으로 작성하는 것이 중요합니다.

상단 새 캔버스를 누르면 현재 캔버스를 보관하고 빈 캔버스를 엽니다. 노드가 있는 캔버스만 왼쪽 칩으로 표시합니다. 빈 캔버스는 칩이 생기지 않으며, 빈 상태에서 새 캔버스를 반복해서 눌러도 빈 항목이 쌓이지 않습니다. 칩은 처음 보관한 시각을 YYYY-MM-DD HH:mm:ss 형식으로 표시하고 다시 열거나 수정해도 시각을 유지합니다. 칩을 눌러 이전 캔버스로 돌아갈 수 있습니다. 칩 옆 삭제하기는 확인 후 해당 개인 캔버스의 이미지·연결·해석·글쓰기 결과를 삭제하며 되돌릴 수 없습니다. 협업 캔버스의 칩은 목록에서만 제거하고 서버의 공유 데이터는 유지합니다. 개인 캔버스 목록은 로그인 계정별로 이 브라우저에 저장되며, 다른 기기로 옮기려면 각 캔버스를 백업하세요.

04 — AI 글쓰기

캔버스 맥락으로 글쓰기

상단 버튼을 누르면 오른쪽에서 넓은 패널이 열리고 캔버스 화면이 왼쪽으로 이동합니다. 닫았다 다시 열어도 입력은 유지됩니다. 작업 백업·복원과 연결 만들기는 글쓰기 패널을 닫은 뒤 사용할 수 있습니다.

  1. API 세팅

    처음 열리는 탭입니다. Gemini, OpenAI, Claude 또는 로컬 OpenAI 호환 API를 선택하고 키·모델을 입력해 설정 저장을 누릅니다. 모델 목록을 불러오거나 모델 ID를 직접 입력할 수 있습니다. 목록을 불러오는 중 연결 정보를 바꾸면 이전 요청은 취소됩니다. 새 설정의 모델 목록을 다시 불러오세요. 로컬 API는 서버 주소도 입력합니다.

    제공자·키·모델을 바꾸면 설정을 다시 저장해야 글쓰기를 요청할 수 있습니다. API 설정은 현재 페이지 메모리에만 보관하며, 브라우저·탭 종료 또는 새로고침·페이지 이동 후에는 다시 입력해야 합니다. 작업 백업에는 포함되지 않으며 설정 저장만으로 글을 생성하지 않습니다.

  2. 가이드 설정

    선택 여부와 관계없이 캔버스 전체의 노드, 연결 방향, 관계 해석, 의견을 글의 재료로 읽습니다. 연결되지 않은 노드도 포함합니다. 문학·비문학, 목적, 독자, 형식, 분량, 관점과 원칙을 정하고 가이드를 저장합니다.

    글의 형식은 비문학에서 설명문·에세이·보고서·칼럼·뉴스 기사, 문학에서 이야기·에세이를 선택합니다. 장르를 오가면 각 장르에서 선택한 형식을 유지합니다. 이전 가이드에 다른 형식이 저장되어 있으면 기존 저장값으로 표시하며 자동으로 바꾸지 않습니다.

    자료나 설정을 바꿨다면 다시 저장합니다. AI에는 저장된 가이드의 텍스트를 전달하며 원본 이미지는 전송하지 않습니다.

  3. 글쓰기 결과물

    AI에게 글쓰기 요청 또는 글 작성 버튼으로 생성을 시작합니다. API 미설정 시에는 설정 안내가 나오며 새 글 생성은 차단됩니다. 이미 저장·공유된 결과물은 읽을 수 있습니다. 탭을 여는 것만으로 AI를 호출하지 않습니다. 가이드에서 글쓰기를 요청하면 결과물 탭으로 포커스가 이동하므로 키보드로 다음 조작을 이어갈 수 있습니다.

    작성 중 취소할 수 있으며 실패하거나 취소해도 이전 결과는 유지됩니다. 결과를 복사하거나 TXT 파일로 내려받을 수 있습니다.

API 사용 요금은 제공자 계정에 부과됩니다. 브라우저 직접 연결이 차단되면 제공자 또는 로컬 서버의 CORS 설정을 확인하세요. 생성된 글은 출처와 사실관계를 검토한 뒤 사용합니다.

형식별 작성 규칙

선택한 형식에 따라 구성과 문체의 작성 규칙을 확인할 수 있습니다. 비문학 에세이와 문학 에세이를 구분한 일곱 가지 작성 계획을 사용합니다. 뉴스 기사는 제목·리드문·본문 순서로 구성하며, 자료에 없는 취재·인용을 만들어 내지 않도록 안내합니다.

가이드를 저장하면 작성 규칙 버전도 기록됩니다. 저장한 가이드의 규칙과 AI 전달 전문을 확인하세요. 버전이 없는 이전 가이드는 현재 규칙을 사용하며, 다시 저장하면 버전이 기록됩니다.

서술 순서와 생성 근거

가이드 설정의 서술 순서에서 AI에게 구성을 맡기거나 노드 순서를 직접 정합니다. 앞으로·뒤로 버튼은 글에서 자료를 제시할 순서만 바꾸며, 캔버스 연결 방향이나 사건의 시간·인과관계를 바꾸지 않습니다. 변경 후 가이드를 저장하세요.

AI에게는 온톨로지 정의 화면과 같은 어휘의 의미 및 저장 당시 노드·연결·해석·의견·반응의 네트워크를 함께 전달합니다. 연결별 대상과 작성자를 구분하고, 해석 없는 연결과 떨어진 자료도 유지합니다. 이 전달은 생성 결과의 의미 검증을 뜻하지 않습니다.

온톨로지 지식 구조에는 저장한 가이드, 당시 자료 사본, AI에게 실제 전달한 입력 원문, 생성 모델과 결과물이 포함됩니다. 가이드를 다시 저장해도 이전 결과의 입력 원문은 유지됩니다. 이전 가이드의 구조화된 자료가 남아 있지 않으면 참조만 표시합니다. 기록되지 않은 요청자나 문단별 근거는 추정하지 않으며, 이 연결이 내용의 사실성을 보증하지는 않습니다.

05 — 온톨로지 구조

구축한 지식의 구조를 확인합니다.

상단 온톨로지 구조를 열면 실제 JSON-LD의 전체 지식 구조가 표시됩니다. 항목을 선택하면 상세 내용, 식별자와 적용되는 제약 정의를 확인할 수 있습니다.

온톨로지 구조는 글쓰기와 같은 오른쪽 슬라이드 패널로 열립니다. 데스크톱에서는 화면 너비의 75%, 800px 이하에서는 전체 너비를 사용하며 캔버스 화면만 왼쪽으로 이동합니다. 보기 드롭다운에서 지식 구조·캔버스 연결·온톨로지 정의를 선택합니다. 글쓰기와 온톨로지 구조는 한 번에 하나씩 표시하고, 전환해도 입력한 글쓰기 설정은 유지합니다. 각 패널의 닫기 버튼으로 캔버스로 돌아옵니다.

지식 구조

이미지·연결·관계 해석·관계 유형·의견·동의와 비토·작성자의 연결을 봅니다. 전체 또는 연결 하나를 범위로 선택합니다.

캔버스 연결

이미지 사이의 방향과 해석을 봅니다. 해석 대기는 점선으로 구분합니다. 연결 이름을 누르면 해당 지식 구조로 이동합니다.

온톨로지 정의

RDF/OWL 어휘와 SHACL 정의의 클래스·속성·제약, 클래스별 데이터 수와 속성 사용 수를 확인합니다.

물리 엔진이 항목 간 간격을 자동으로 조정합니다. 자동 배치 멈추기·시작으로 움직임을 제어하고, 휠 확대·축소, 빈 공간 이동, 항목 드래그를 사용할 수 있습니다. 같은 두 항목의 양방향·복수 관계는 곡선을 나누어 표시합니다. 키보드로는 항목 선택 목록에서 노드와 관계를 확인합니다. 시각화 배치는 원본 캔버스를 변경하지 않습니다. JSON-LD 내보내기 버튼은 관리자 계정에서만 활성화됩니다. 다운로드 시 온라인으로 관리자 인증을 확인합니다. 작업 백업·복원 권한은 이 제한과 별개입니다.

SHACL 제약 정의를 표시하는 것은 검증 실행과 다릅니다. 현재 화면은 자동 추론 결과나 변경 이력 재생을 제공하지 않습니다.

06 — 백업·복원과 작성자

작업은 백업으로 보관합니다.

로그인하지 않은 상태로 시작하면 로그인·협업 탭을 먼저 엽니다. 로그인 전에는 슬라이드의 닫기 버튼이 비활성화되며, 로그인에 성공하면 닫기 버튼으로 캔버스에 진입합니다. 별도의 캔버스 중앙 로그인 안내는 표시하지 않습니다. 로그아웃하면 로그인 슬라이드가 다시 열리고 닫기가 비활성화됩니다. 작업 데이터는 지우지 않습니다. 로그아웃 버튼은 로그인·협업 탭 상단의 로그인한 계정 카드에 있습니다. 로그인 세션이 유지되어 있으면 캔버스로 시작합니다. 개인 캔버스의 이름은 가입 시 로그인 ID로 입력한 이메일을 사용해 ‘이메일의 맥락’으로 표시합니다. 협업 캔버스에서는 해당 캔버스 이름을 표시합니다. 로그인·협업과 작업 백업·복원은 상단의 한 버튼으로 여는 슬라이드 패널에 모았습니다. 글쓰기와 같은 너비(데스크톱 75vw, 800px 이하 전체 너비)를 사용합니다. 로그인·협업과 작업 백업·복원 탭을 전환하며, 파일 백업·복원에는 로그인이 필요하지 않습니다. 닫기 버튼으로 종료하고, 키보드 좌우 방향키와 Home·End로 탭을 이동할 수 있습니다.

위치역할
작업 백업·복원이미지·노드·관계·의견·저장된 글쓰기 가이드와 결과를 JSON 파일로 백업하고 복원합니다.
온톨로지 구조의 JSON-LD 내보내기지식 그래프를 외부 도구로 전달합니다. 작업 복원 파일은 아닙니다.
작성자 설정 (데스크톱은 작업 이름 옆, 작은 화면은 상단 메뉴)이후 작성할 내용의 표시 이름을 바꿉니다. 기존 작성자·소유권은 변경하지 않습니다.

브라우저에 자동 저장됩니다. 하단 저장 상태를 확인하고, 다른 기기나 폴더로 옮기기 전에는 백업하세요. 브라우저 저장이 불가능할 때도 백업 파일을 사용할 수 있습니다.

백업 불러오기는 합치기가 아니라 현재 작업 교체입니다. 파일을 선택하면 노드·연결 수와 교체 안내가 나옵니다. 현재 작업을 백업하고 불러오기를 누르면 현재 작업을 내려받고 불러온 작업으로 교체합니다. 다른 브라우저에서는 이전 노드의 소유자로 인식되지 않을 수 있습니다.

07 — 협업과 온라인 보관

같은 캔버스에서 함께 작업합니다.

  1. 상단 계정 및 작업 관리를 열고 로그인·협업 탭에서 로그인합니다.

    이메일 가입 후 인증을 완료합니다. 로그인만으로 현재 작업이 공유되지는 않습니다.

  2. 현재 작업으로 협업 시작을 엽니다.

    이름을 정하고 협업 사본을 만듭니다. 사본의 생성자는 내 계정이 되고 기존 표시 작성자는 유지됩니다. 기존 반응은 계정 미확인 이력으로 구분합니다. 원래 로컬 작업은 그대로 남습니다.

  3. 초대 코드를 전달합니다.

    협업 관리에서 코드를 만들고 원하는 참여자에게 직접 전달합니다. 참여자는 로그인 후 초대 코드로 참여합니다. 코드는 7일간 유효하며 관리자가 취소하거나 교체할 수 있습니다.

  4. 이미지를 놓고 해석·의견을 저장합니다.

    항목별 변경 사항이 DB에 자동 저장되어 다른 참여자의 화면에 반영됩니다. 하단에서 서버 저장·대기·실패 상태를 확인하세요. 입력 중에는 다른 참여자의 변경 반영을 기다립니다.

공유하는 데이터개인에게만 남는 정보
이미지·노드 배치·출처·해석·방향 연결·관계 정의·의견·동의/비토·저장한 가이드·글쓰기 결과API 세팅의 제공자·모델·키·서버 주소, 로그인 토큰, 현재 선택과 확대 배율

결과에 기록된 생성 모델명은 출처 정보입니다. 다른 사람의 API 설정을 넘겨받아 사용하지 않습니다. API 설정 없이도 공유된 결과물은 읽을 수 있으며, 새 글을 요청할 때는 자신의 API 설정이 필요합니다.

권한과 충돌 처리

노드 해석 수정·삭제, 연결 삭제, 의견 삭제는 각 생성자만 가능합니다. 참여자는 노드를 배치하고 새 이미지·연결·해석·의견을 추가할 수 있습니다. 노드를 삭제하면 연결과 그 아래 해석·의견도 삭제됩니다. 협업 삭제는 확인 후 실행하며 되돌릴 수 없습니다.

같은 항목을 동시에 수정하면 나중 변경을 강제로 덮어쓰지 않습니다. 내 변경을 남겨 두고 안내합니다. 협업 관리에서 내 작업 백업 후 최신 내용 불러오기를 선택해 비교하세요. 서로 다른 항목의 변경은 함께 반영합니다. 입력 문자나 마우스 커서를 실시간으로 공유하는 방식은 아닙니다.

통신 실패 시 미전송 변경은 이 브라우저에 별도로 보관합니다. 저장 다시 시도로 연결을 확인할 수 있고, 같은 탭에서 같은 계정으로 해당 캔버스를 다시 열면 미전송 작업을 복구합니다. 탭을 완전히 닫기 전에는 미전송 변경을 파일로 백업하세요. 로컬 작업으로 돌아가거나 로그아웃하면 이전 로컬 캔버스를 보여줍니다.

개인 온라인 사본

로그인·협업 탭의 개인 온라인 사본 보관을 펼치면 개인 사본을 저장·불러올 수 있습니다. 일반 사용자는 자신의 사본만 조회합니다. 이 기능은 자동 동기화가 아니며 매번 새 사본을 저장합니다. 최근 50개 사본을 표시하고 일반 사용자에게는 사본 삭제 버튼이 없습니다. 관리자는 콘텐츠 관리에서 사본을 숨기거나 삭제할 수 있습니다.

캔버스 목록과 작업 영역

데스크톱에서는 내 캔버스 목록을 왼쪽에 배치합니다. 목록 아래까지 이어지는 영역은 공통 색상 토큰의 쿨화이트 배경과 얇은 오른쪽 경계선으로 캔버스와 구분합니다. 800px 이하에서는 목록을 캔버스 위의 가로 스크롤 행으로 표시합니다. 저장된 캔버스를 열면 실제 작업 영역에 맞춰 노드가 보이도록 화면을 보정합니다.

관리자 전용 관리

관리자 계정에는 작업 백업·복원 다음에 사용자 관리와 콘텐츠 관리 탭이 표시됩니다. 사용자별 온라인 콘텐츠를 확인하고 협업 캔버스·공유 결과물·개인 온라인 사본을 숨기거나 삭제할 수 있습니다. 숨김은 해제할 수 있고 삭제는 되돌릴 수 없습니다. 각 기기에만 저장된 캔버스와 이미 내려받은 사본은 관리 대상이 아닙니다.

디자인 시스템 접근과 저장 상태

도네이션

상단 새 캔버스 앞의 도네이션 버튼에서 후원 안내를 엽니다. 계좌번호는 끝 3자리만 표시하며 복사 기능은 제공하지 않습니다. 토스 후원 버튼으로 송금 화면을 열 수 있으며 데스크톱에서는 QR 코드를 표시합니다. 모달은 닫기 버튼으로 닫습니다. 후원은 자율입니다.

디자인 시스템 링크는 worflogy@gmail.com 관리자 인증이 확인될 때 활성화됩니다. 일반 사용자와 비로그인 사용자에게는 비활성화됩니다. 사용 가이드는 누구나 읽을 수 있습니다.

로컬 표시는 현재 브라우저에 보관하는 작업이라는 뜻입니다. 로그인 자체가 업로드를 뜻하지 않습니다. 개인 온라인 사본은 직접 저장하고, 협업 캔버스는 변경 사항을 서버에 동기화합니다. 하단 저장 상태를 확인하세요.

관리자는 온라인 콘텐츠를 숨김·해제·삭제할 수 있습니다. 다른 사용자의 계정을 삭제하거나 이용을 정지시키는 관리자 기능은 제공하지 않습니다. 본인의 회원 탈퇴·계정 삭제는 로그인·협업 탭에서 별도로 제공합니다. 콘텐츠 삭제 후에도 재사용 중인 이미지 파일은 저장소에 남을 수 있습니다.

작성자 표시

기본 작성자 이름은 로그인 ID(이메일)입니다. 새 캔버스에도 로그인 ID를 사용합니다. 사용자가 설정한 이름과 기존 기록은 유지합니다. 본인이 작성한 노드·관계 해석·의견에는 화면에서만 (나)를 덧붙이고 다른 참여자에게는 저장된 이름을 표시합니다. 본인 여부와 수정·삭제 권한은 이름이 아닌 소유자 ID로 구분합니다. 생성자를 확인할 수 없는 기존 기록에는 (나)를 붙이지 않습니다.

화면 언어

상단 한국어·English 버튼으로 화면 언어를 바꿉니다. 입력 중인 내용과 캔버스 데이터는 유지됩니다. 사용자 기록과 기존 AI 결과는 자동 번역하지 않습니다. 영어 화면에서 새 AI 글쓰기를 요청하면 영어로 작성하도록 지시합니다.

화면의 한글 제목은 SUITE, 영문 제목은 Space Grotesk, 본문과 입력은 Pretendard로 표시합니다. 큰따옴표와 작은따옴표는 수직형으로 보이지만, 입력한 원문과 복사·저장한 문자는 바뀌지 않습니다.

저장된 관계 해석 관리

등록한 의견의 본문을 수정하는 기능은 없습니다. 협업에서는 작성자 본인만 의견을 삭제할 수 있으며, 삭제하면 해당 의견의 동의·비토도 함께 삭제됩니다. 관계 해석의 수정·삭제와는 별도 기능입니다.

저장된 관계 해석은 관계명 아래의 해석 수정·해석 삭제 버튼으로 관리합니다. 작성자만 변경할 수 있습니다. 수정 시 기존 의견과 동의·비토는 유지하며, 삭제 시 해당 해석의 의견과 반응도 함께 삭제합니다. 연결선과 다른 해석은 유지됩니다.

연결 방향 바꾸기

연결을 선택하면 출발 이미지와 도착 이미지가 표시됩니다. 연결 작성자는 방향 바꾸기로 화살표를 반대로 바꿀 수 있습니다. 해석과 의견은 그대로 유지되므로 새 방향에 맞는지 확인해야 합니다. 협업에서는 DB의 방향 변경 업데이트가 적용되어 있어야 합니다.

확인과 알림

삭제와 중요한 변경은 앱 내부 확인창에서 대상과 영향을 확인합니다. 취소에 기본 초점을 두고, 삭제·전환 등 실제 동작 이름을 버튼에 표시합니다. 닫기와 취소는 작업을 실행하지 않습니다. 바깥 영역과 Esc로는 닫히지 않습니다. 완료 안내는 토스트로, 입력 오류는 해당 입력 근처에 표시합니다.

글의 재료 확인

글의 재료 확인은 상단의 이미지·연결·관계 해석·의견 수로 요약합니다. 이미지 목록에서 해석과 출처를, 연결 목록에서 출발·도착과 관계 해석·의견을 펼쳐볼 수 있습니다. 목록의 펼침 여부와 관계없이 캔버스 전체 자료가 가이드에 포함되며, 원본 이미지 파일은 AI에 전송하지 않습니다.

AI에게 전달할 가이드

AI에게 전달할 가이드는 저장한 목적·독자·형식·관점·서술 순서·작성 원칙을 요약해서 보여줍니다. 실제 전달 문서는 AI 전달 전문 보기에서 펼쳐 확인합니다. 요약만 표시되더라도 복사·내려받기·AI 요청에는 온톨로지와 캔버스 자료를 포함한 전문을 사용합니다.

해석 패널

노드 해석은 이미지와 이름, 출처, 해석 입력, 저장 순서로 구성합니다. 관계 해석은 연결 방향과 해석 목록을 먼저 보여주고, 선택한 해석의 정의와 작성자·수정·삭제를 하나의 카드에 배치합니다. 의견 입력은 의견 남기기를 펼쳐 작성하며, 등록된 의견은 등록순으로 읽고 동의·비토할 수 있습니다. 작성자 권한은 기존과 동일하게 적용합니다.

글쓰기 결과 읽기

참조는 현재 캔버스가 아니라 해당 글을 작성할 때 AI에게 전달한 자료에서 찾습니다. AI가 식별자의 id-만 빠뜨렸고 같은 가이드·자료 종류·전체 UUID가 정확히 일치하면 해당 자료로 연결합니다. 대괄호 안의 id-전체 UUID나 id-와 UUID 첫 8자리로 된 축약 참조도 작성 당시 자료에서 후보가 하나일 때 연결합니다. 노드·연결·해석·의견 종류가 명시되어 있으면 해당 종류 안에서 찾습니다. 후보가 없거나 여러 개면 미확인 참조로 남깁니다.

미확인 참조가 남으면 원본 식별자와 AI 응답 원문 보기를 펼쳐 확인하세요. 참조 번호가 있어도 자료 연결이나 사실 검증을 보장하지 않습니다. 결과 복사·내려받기에도 미확인 상태가 표시됩니다.

식별자 보정은 읽기용 표시에서만 적용합니다. 이미 저장된 결과에도 적용되며 AI 응답 원문과 입력 자료는 바꾸지 않습니다.

글쓰기 결과는 제목, 문단, 강조, 목록을 구분해 표시합니다. 긴 식별자는 본문에서 번호로 줄이고 글 아래 참조 자료에서 작성 당시의 노드 해석과 관계 해석을 확인합니다. 자료에서 찾지 못한 식별자는 미확인 참조로 표시합니다. 출처 번호는 사실 검증을 의미하지 않습니다.

결과 복사와 내려받기는 읽기용 본문과 참조 목록을 제공합니다. AI 응답 원문 보기에서는 식별자와 Markdown이 포함된 원문을 확인할 수 있습니다. 저장된 원문과 AI 입력 자료는 변경하지 않습니다.

마지막 캔버스 이어서 작업

같은 브라우저에서 새로고침하거나 사용자 가이드·디자인 시스템에서 돌아오면 로그인 계정별로 마지막에 열었던 캔버스를 다시 엽니다. 협업 캔버스는 서버 접근 권한을 확인한 뒤 연결하며, 열지 못하면 개인 캔버스를 표시하고 안내합니다. 로컬 작업으로 돌아가기를 선택하면 다음에도 해당 개인 캔버스로 시작합니다. 이 기능은 다른 기기까지 마지막 선택을 동기화하지 않습니다.

Google 계정으로 로그인

Google로 계속하기를 누르면 Google 계정을 선택한 뒤 캔버스로 돌아옵니다. 기존 작업을 이어가려면 가입할 때 사용한 이메일의 Google 계정을 선택하세요. Google 연결 설정이 아직 완료되지 않았다면 이메일 로그인을 사용할 수 있습니다. Google 로그인은 게시된 사이트 또는 localhost에서 지원하며, 파일을 직접 연 화면에서는 사용할 수 없습니다.

회원 탈퇴·계정 삭제

계정 및 작업 관리의 로그인·협업 탭에서 회원 탈퇴·계정 삭제를 펼치세요. 삭제 범위를 확인하고 로그인 이메일을 입력한 뒤 영구 삭제에 동의하세요. 필요한 작업은 먼저 백업해 주세요. 로컬 작업과 다운로드 파일은 남습니다.

  • 개인 온라인 사본과 해당 이미지, 본인 소유 협업 캔버스를 삭제합니다. 본인 소유 캔버스에 있는 다른 참여자의 기록도 함께 삭제됩니다.
  • 다른 사람이 소유한 캔버스에 남긴 기록과 이미지는 유지하고 작성자 표시를 ‘탈퇴한 사용자’로 바꿉니다. 과거 기여 식별값, 본문이나 과거 사본에 직접 적힌 이름까지 자동으로 지우지는 않습니다.
  • 이 브라우저의 로컬 작업과 내려받은 파일은 남습니다. Google 계정이나 외부 AI 계정도 삭제되지 않습니다.
  • 삭제 도중 오류가 발생하면 일부 데이터가 이미 삭제됐을 수 있습니다. 같은 계정으로 다시 시도하고, 계속 실패하면 개인정보 처리방침의 연락처로 문의하세요. 관리자 감사기록 등 별도 보존 항목은 개인정보 처리방침의 보유기간을 따릅니다.

AI API 설정의 보관 기간

AI 제공자·모델·API 키·서버 주소는 현재 페이지 메모리에만 유지합니다. 브라우저나 탭을 닫거나 새로고침·페이지 이동을 하면 다시 입력해야 합니다. 이전에 브라우저 저장소에 보관했던 API 설정도 제거합니다. 캔버스, 저장한 글쓰기 가이드와 결과물은 유지합니다.

문서 탐색과 법적 고지

사용 가이드와 디자인 시스템은 같은 헤더·목차·본문 레이아웃을 사용합니다. 상단의 캔버스 돌아가기, 문서 이동, 언어 버튼은 스크롤 중에도 보입니다. 목차를 누르면 제목이 고정 헤더 아래에 나타납니다.

하단의 이용약관과 개인정보 처리방침은 로그인하지 않아도 모달로 읽을 수 있습니다. 캔버스·사용 가이드·디자인 시스템에서 같은 방식으로 열립니다. 문서 본문만 스크롤되고 제목과 닫기 버튼은 위에 유지됩니다.

모달은 닫기 버튼으로만 닫습니다. 바깥 영역 클릭과 Esc는 닫지 않으며, 닫은 뒤에는 열었던 링크로 키보드 초점이 돌아옵니다. 모달 열기는 페이지 이동이 아니므로 현재 캔버스와 입력 중인 API 설정을 유지합니다.

영문 화면에서도 법률 문서 본문은 한국어로 제공하며 링크에 Korean을 표시합니다. 화면 언어 전환이 법률 문서의 영문 번역을 제공하는 것은 아닙니다.
