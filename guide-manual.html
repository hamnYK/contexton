01 — 시작과 화면 조작

빈 캔버스에서 시작합니다.

이미지를 놓고 생각을 연결한 뒤, 그 맥락을 AI에게 전달할 글쓰기 가이드로 만듭니다. 처음에는 예시 노드가 없습니다. 로그인 후 빈 캔버스 중앙에 이미지 드래그 안내가 표시되고, 노드가 생기면 사라집니다. 저장된 작업이 있으면 같은 브라우저와 경로에서 불러옵니다.

캔버스에서 시작하기

02 — 이미지와 노드

이미지를 놓으면 노드가 됩니다.

  1. 빈 캔버스에 이미지를 드래그앤드롭합니다.

    썸네일 노드가 즉시 생성됩니다. PNG·JPEG·WebP, 이미지당 최대 2MB를 지원합니다.

  2. 노드 해석에서 출처와 해석을 적습니다.

    이미지 출처(최대 500자)와 해석(최대 200자)을 입력하고 저장합니다.

  3. 노드를 다시 클릭해 수정합니다.

    저장된 출처나 해석이 있으면 버튼이 수정으로 표시됩니다.

기존 노드 위에 새 이미지를 놓으면 원래 이미지는 유지되고, 겹치지 않는 위치에 새 노드와 기존 노드에서 새 노드로 향하는 연결이 생성됩니다. 새 노드 내용을 먼저 입력하고, 관계 해석은 나중에 링크를 클릭해 작성합니다.

수정과 삭제

로컬 모드에서는 브라우저 식별자, 협업 모드에서는 로그인 계정 ID를 기준으로 노드 출처·해석 수정과 삭제를 허용합니다. 생성자를 확인할 수 없는 기존 노드는 읽기 전용입니다. 표시 이름을 바꿔도 소유권은 바뀌지 않습니다.

선택 후 상단 삭제를 실행합니다. 노드를 지우면 붙어 있는 링크도 삭제되며, 연결된 다른 노드는 남습니다. 로컬 모드에서는 삭제 되돌리기를 사용할 수 있습니다. 협업 모드는 삭제 전 확인을 거치며 되돌리기를 지원하지 않습니다. Delete·Backspace 단축키는 캔버스에 포커스가 있을 때만 적용하며, 글쓰기 패널이 열려 있으면 적용하지 않습니다.

03 — 연결과 관계 해석

한 연결에 여러 해석을 쌓습니다.

  1. 기존 노드끼리는 연결 만들기를 누릅니다.

    시작 노드와 도착 노드를 차례로 클릭합니다. 연결에는 방향이 있습니다.

  2. 관계 계열과 하위 관계를 고릅니다.

    링크 옆 편집창에서 관계의 정의를 적습니다. 다른 해석 추가로 여러 해석을 작성한 뒤 저장할 수 있습니다.

  3. 저장된 해석에 의견을 남깁니다.

    의견은 등록 순서대로 표시됩니다. 각 의견에 동의 또는 비토를 표시하고, 자신의 반응을 바꾸거나 취소할 수 있습니다.

의견 삭제는 해당 의견과 그에 달린 동의·비토를 삭제합니다. 관계 해석이나 노드까지 지우지는 않습니다. 링크 자체를 삭제하려면 캔버스에서 링크를 선택한 뒤 상단 삭제를 사용합니다.

관계 이름이 ‘원인’이더라도 작성자가 제안한 해석입니다. 온톨로지가 인과관계를 사실로 판정한 것은 아닙니다.

상단 새 캔버스를 누르면 현재 캔버스를 보관하고 빈 캔버스를 엽니다. 노드가 있는 캔버스만 왼쪽 칩으로 표시합니다. 빈 캔버스는 칩이 생기지 않으며, 빈 상태에서 새 캔버스를 반복해서 눌러도 빈 항목이 쌓이지 않습니다. 칩은 처음 보관한 시각을 YYYY-MM-DD HH:mm:ss 형식으로 표시하고 다시 열거나 수정해도 시각을 유지합니다. 칩을 눌러 이전 캔버스로 돌아갈 수 있습니다. 칩 옆 삭제하기는 확인 후 해당 개인 캔버스의 이미지·연결·해석·글쓰기 결과를 삭제하며 되돌릴 수 없습니다. 협업 캔버스의 칩은 목록에서만 제거하고 서버의 공유 데이터는 유지합니다. 개인 캔버스 목록은 로그인 계정별로 이 브라우저에 저장되며, 다른 기기로 옮기려면 각 캔버스를 백업하세요.

04 — AI 글쓰기

캔버스 맥락으로 글쓰기

상단 버튼을 누르면 오른쪽에서 넓은 패널이 열리고 캔버스 화면이 왼쪽으로 이동합니다. 닫았다 다시 열어도 입력은 유지됩니다. 작업 백업·복원과 연결 만들기는 글쓰기 패널을 닫은 뒤 사용할 수 있습니다.

1. API 세팅2. 가이드 설정3. 글쓰기 결과물
  1. API 세팅

    처음 열리는 탭입니다. Gemini, OpenAI, Claude 또는 로컬 OpenAI 호환 API를 선택하고 키·모델을 입력해 설정 저장을 누릅니다. 모델 목록을 불러오거나 모델 ID를 직접 입력할 수 있습니다. 목록을 불러오는 중 연결 정보를 바꾸면 이전 요청은 취소됩니다. 새 설정의 모델 목록을 다시 불러오세요. 로컬 API는 서버 주소도 입력합니다.

    제공자·키·모델을 바꾸면 설정을 다시 저장해야 글쓰기를 요청할 수 있습니다. 키는 현재 탭 세션에 보관되며 작업 백업에 포함되지 않습니다. 설정 저장만으로 글을 생성하지 않습니다.

  2. 가이드 설정

    선택 여부와 관계없이 캔버스 전체의 노드, 연결 방향, 관계 해석, 의견을 글의 재료로 읽습니다. 연결되지 않은 노드도 포함합니다. 문학·비문학, 목적, 독자, 형식, 분량, 관점과 원칙을 정하고 가이드를 저장합니다.

    자료나 설정을 바꿨다면 다시 저장합니다. AI에는 저장된 가이드의 텍스트를 전달하며 원본 이미지는 전송하지 않습니다.

  3. 글쓰기 결과물

    AI에게 글쓰기 요청 또는 글 작성 버튼으로 생성을 시작합니다. API 미설정 시에는 설정 안내가 나오며 새 글 생성은 차단됩니다. 이미 저장·공유된 결과물은 읽을 수 있습니다. 탭을 여는 것만으로 AI를 호출하지 않습니다. 가이드에서 글쓰기를 요청하면 결과물 탭으로 포커스가 이동하므로 키보드로 다음 조작을 이어갈 수 있습니다.

    작성 중 취소할 수 있으며 실패하거나 취소해도 이전 결과는 유지됩니다. 결과를 복사하거나 TXT 파일로 내려받을 수 있습니다.

API 사용 요금은 제공자 계정에 부과됩니다. 브라우저 직접 연결이 차단되면 제공자 또는 로컬 서버의 CORS 설정을 확인하세요. 생성된 글은 출처와 사실관계를 검토한 뒤 사용합니다.

서술 순서와 생성 근거

가이드 설정의 서술 순서에서 AI에게 구성을 맡기거나 노드 순서를 직접 정합니다. 앞으로·뒤로 버튼은 글에서 자료를 제시할 순서만 바꾸며, 캔버스 연결 방향이나 사건의 시간·인과관계를 바꾸지 않습니다. 변경 후 가이드를 저장하세요.

AI에게는 온톨로지 정의 화면과 같은 어휘의 의미 및 저장 당시 노드·연결·해석·의견·반응의 네트워크를 함께 전달합니다. 연결별 대상과 작성자를 구분하고, 해석 없는 연결과 떨어진 자료도 유지합니다. 이 전달은 생성 결과의 의미 검증을 뜻하지 않습니다.

온톨로지 지식 구조에는 저장한 가이드, 당시 자료 사본, AI에게 실제 전달한 입력 원문, 생성 모델과 결과물이 포함됩니다. 가이드를 다시 저장해도 이전 결과의 입력 원문은 유지됩니다. 이전 가이드의 구조화된 자료가 남아 있지 않으면 참조만 표시합니다. 기록되지 않은 요청자나 문단별 근거는 추정하지 않으며, 이 연결이 내용의 사실성을 보증하지는 않습니다.

05 — 온톨로지 구조

구축한 지식의 구조를 확인합니다.

상단 온톨로지 구조를 열면 실제 JSON-LD의 전체 지식 구조가 표시됩니다. 항목을 선택하면 상세 내용, 식별자와 적용되는 제약 정의를 확인할 수 있습니다.

온톨로지 구조는 글쓰기와 같은 오른쪽 슬라이드 패널로 열립니다. 데스크톱에서는 화면 너비의 75%, 800px 이하에서는 전체 너비를 사용하며 캔버스 화면만 왼쪽으로 이동합니다. 보기 드롭다운에서 지식 구조·캔버스 연결·온톨로지 정의를 선택합니다. 글쓰기와 온톨로지 구조는 한 번에 하나씩 표시하고, 전환해도 입력한 글쓰기 설정은 유지합니다. 각 패널의 닫기 버튼으로 캔버스로 돌아옵니다.

지식 구조

이미지·연결·관계 해석·관계 유형·의견·동의와 비토·작성자의 연결을 봅니다. 전체 또는 연결 하나를 범위로 선택합니다.

캔버스 연결

이미지 사이의 방향과 해석을 봅니다. 해석 대기는 점선으로 구분합니다. 연결 이름을 누르면 해당 지식 구조로 이동합니다.

온톨로지 정의

RDF/OWL 어휘와 SHACL 정의의 클래스·속성·제약, 클래스별 데이터 수와 속성 사용 수를 확인합니다.

물리 엔진이 항목 간 간격을 자동으로 조정합니다. 자동 배치 멈추기·시작으로 움직임을 제어하고, 휠 확대·축소, 빈 공간 이동, 항목 드래그를 사용할 수 있습니다. 같은 두 항목의 양방향·복수 관계는 곡선을 나누어 표시합니다. 키보드로는 항목 선택 목록에서 노드와 관계를 확인합니다. 시각화 배치는 원본 캔버스를 변경하지 않습니다. JSON-LD 내보내기 버튼은 관리자 계정에서만 활성화됩니다. 다운로드 시 온라인으로 관리자 인증을 확인합니다. 작업 백업·복원 권한은 이 제한과 별개입니다.

SHACL 제약 정의를 표시하는 것은 검증 실행과 다릅니다. 현재 화면은 자동 추론 결과나 변경 이력 재생을 제공하지 않습니다.

06 — 백업·복원과 작성자

작업은 백업으로 보관합니다.

로그인하지 않은 상태로 시작하면 로그인·협업 탭을 먼저 엽니다. 로그인 전에는 슬라이드의 닫기 버튼이 비활성화되며, 로그인에 성공하면 닫기 버튼으로 캔버스에 진입합니다. 별도의 캔버스 중앙 로그인 안내는 표시하지 않습니다. 로그아웃하면 로그인 슬라이드가 다시 열리고 닫기가 비활성화됩니다. 작업 데이터는 지우지 않습니다. 로그아웃 버튼은 로그인·협업 탭 상단의 로그인한 계정 카드에 있습니다. 로그인 세션이 유지되어 있으면 캔버스로 시작합니다. 개인 캔버스의 이름은 가입 시 로그인 ID로 입력한 이메일을 사용해 ‘이메일의 맥락’으로 표시합니다. 협업 캔버스에서는 해당 캔버스 이름을 표시합니다. 로그인·협업과 작업 백업·복원은 상단의 한 버튼으로 여는 슬라이드 패널에 모았습니다. 글쓰기와 같은 너비(데스크톱 75vw, 800px 이하 전체 너비)를 사용합니다. 로그인·협업과 작업 백업·복원 탭을 전환하며, 파일 백업·복원에는 로그인이 필요하지 않습니다. 닫기 버튼으로 종료하고, 키보드 좌우 방향키와 Home·End로 탭을 이동할 수 있습니다.

위치역할
작업 백업·복원이미지·노드·관계·의견·저장된 글쓰기 가이드와 결과를 JSON 파일로 백업하고 복원합니다.
온톨로지 구조의 JSON-LD 내보내기지식 그래프를 외부 도구로 전달합니다. 작업 복원 파일은 아닙니다.
작성자 설정 (데스크톱은 작업 이름 옆, 작은 화면은 상단 메뉴)이후 작성할 내용의 표시 이름을 바꿉니다. 기존 작성자·소유권은 변경하지 않습니다.

브라우저에 자동 저장됩니다. 하단 저장 상태를 확인하고, 다른 기기나 폴더로 옮기기 전에는 백업하세요. 브라우저 저장이 불가능할 때도 백업 파일을 사용할 수 있습니다.

백업 불러오기는 합치기가 아니라 현재 작업 교체입니다. 파일을 선택하면 노드·연결 수와 교체 안내가 나옵니다. 현재 작업을 백업하고 불러오기를 누르면 현재 작업을 내려받고 불러온 작업으로 교체합니다. 다른 브라우저에서는 이전 노드의 소유자로 인식되지 않을 수 있습니다.

07 — 협업과 온라인 보관

같은 캔버스에서 함께 작업합니다.

  1. 상단 계정 및 작업 관리를 열고 로그인·협업 탭에서 로그인합니다.

    이메일 가입 후 인증을 완료합니다. 로그인만으로 현재 작업이 공유되지는 않습니다.

  2. 현재 작업으로 협업 시작을 엽니다.

    이름을 정하고 협업 사본을 만듭니다. 사본의 생성자는 내 계정이 되고 기존 표시 작성자는 유지됩니다. 기존 반응은 계정 미확인 이력으로 구분합니다. 원래 로컬 작업은 그대로 남습니다.

  3. 초대 코드를 전달합니다.

    협업 관리에서 코드를 만들고 원하는 참여자에게 직접 전달합니다. 참여자는 로그인 후 초대 코드로 참여합니다. 코드는 7일간 유효하며 관리자가 취소하거나 교체할 수 있습니다.

  4. 이미지를 놓고 해석·의견을 저장합니다.

    항목별 변경 사항이 DB에 자동 저장되어 다른 참여자의 화면에 반영됩니다. 하단에서 서버 저장·대기·실패 상태를 확인하세요. 입력 중에는 다른 참여자의 변경 반영을 기다립니다.

공유하는 데이터개인에게만 남는 정보
이미지·노드 배치·출처·해석·방향 연결·관계 정의·의견·동의/비토·저장한 가이드·글쓰기 결과API 세팅의 제공자·모델·키·서버 주소, 로그인 토큰, 현재 선택과 확대 배율

결과에 기록된 생성 모델명은 출처 정보입니다. 다른 사람의 API 설정을 넘겨받아 사용하지 않습니다. API 설정 없이도 공유된 결과물은 읽을 수 있으며, 새 글을 요청할 때는 자신의 API 설정이 필요합니다.

권한과 충돌 처리

노드 해석 수정·삭제, 연결 삭제, 의견 삭제는 각 생성자만 가능합니다. 참여자는 노드를 배치하고 새 이미지·연결·해석·의견을 추가할 수 있습니다. 노드를 삭제하면 연결과 그 아래 해석·의견도 삭제됩니다. 협업 삭제는 확인 후 실행하며 되돌릴 수 없습니다.

같은 항목을 동시에 수정하면 나중 변경을 강제로 덮어쓰지 않습니다. 내 변경을 남겨 두고 안내합니다. 협업 관리에서 내 작업 백업 후 최신 내용 불러오기를 선택해 비교하세요. 서로 다른 항목의 변경은 함께 반영합니다. 입력 문자나 마우스 커서를 실시간으로 공유하는 방식은 아닙니다.

통신 실패 시 미전송 변경은 이 브라우저에 별도로 보관합니다. 저장 다시 시도로 연결을 확인할 수 있고, 같은 탭에서 같은 계정으로 해당 캔버스를 다시 열면 미전송 작업을 복구합니다. 탭을 완전히 닫기 전에는 미전송 변경을 파일로 백업하세요. 로컬 작업으로 돌아가거나 로그아웃하면 이전 로컬 캔버스를 보여줍니다.

개인 온라인 사본

로그인·협업 탭의 개인 온라인 사본 보관을 펼치면 개인 사본을 저장·불러올 수 있습니다. 일반 사용자는 자신의 사본만 조회합니다. 이 기능은 자동 동기화가 아니며 매번 새 사본을 저장합니다. 최근 50개 사본을 표시하고 일반 사용자에게는 사본 삭제 버튼이 없습니다. 관리자는 콘텐츠 관리에서 사본을 숨기거나 삭제할 수 있습니다.

캔버스 목록과 작업 영역

데스크톱에서는 왼쪽 캔버스 목록과 작업 영역을 분리합니다. 800px 이하에서는 목록을 캔버스 위의 가로 스크롤 행으로 표시하여 노드나 빈 공간의 조작을 가리지 않습니다.

관리자 전용 관리

관리자 계정에는 작업 백업·복원 다음에 사용자 관리와 콘텐츠 관리 탭이 표시됩니다. 사용자별 온라인 콘텐츠를 확인하고 협업 캔버스·공유 결과물·개인 온라인 사본을 숨기거나 삭제할 수 있습니다. 숨김은 해제할 수 있고 삭제는 되돌릴 수 없습니다. 각 기기에만 저장된 캔버스와 이미 내려받은 사본은 관리 대상이 아닙니다.
