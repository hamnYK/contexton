명확한 구획직접 조작다른 관점의 공존

캔버스·편집창·슬라이드·사용자 가이드에 같은 색상·폰트·간격을 적용합니다. 예시 입력은 이 화면에서만 유지되며 실제 캔버스·계정·AI 설정에 저장되지 않습니다.

01

설명보다 자연스러운 조작

이미지에서 시작

빈 캔버스에 이미지를 놓으면 노드가 됩니다. 기존 노드 위에 놓으면 새 노드와 연결이 함께 생깁니다. 노드 추가 메뉴는 두지 않습니다.

대상 곁에서 해석

노드와 연결을 클릭하면 해당 대상을 가리키는 편집창을 엽니다. 출처·정의·해석을 문맥 안에서 읽고 수정합니다.

관점과 사실을 구분

관계는 작성자의 해석입니다. 의견과 동의·비토를 함께 보여주되, 반응의 수를 사실 여부로 표현하지 않습니다.

02

행동, 선택, 관계를 구분하는 색

코랄 계열은 주요 실행, 스카이 계열은 작업 영역의 구분에 사용합니다. 선택은 진한 파란 외곽선으로 표시하며, 관계의 계열과 상태는 문자도 함께 표시합니다.

목록 배경은 쿨화이트, 캔버스는 옅은 블루, 경계선은 공통 테두리 색을 사용합니다. 실제 화면과 아래 색상 견본은 같은 토큰을 참조하며, 개별 화면에서 별도의 색상값을 지정하지 않습니다.

편집창 안내선은 중립색 점선입니다. 실제 연결은 실선과 채워진 삼각형 화살표로 표시해 안내선과 구분합니다.

04

입력과 실행 사이에 여유를 둡니다

간격

라벨과 입력 8px, 입력 항목 사이 16px, 마지막 입력과 저장 버튼 16px, 카드 안쪽 24px. 조작 요소 4px·카드 6px 모서리를 사용합니다.

상태와 접근성

선택·포커스·저장 중·읽기 전용을 구분합니다. 터치 영역은 최소 44px로 유지하며, 삭제는 선택과 별도 행동으로 제공합니다.

06

하나의 연결에 여러 해석

기존 노드끼리는 ‘연결 만들기’에서 시작·도착 노드를 선택합니다. 이미지 드롭으로 생긴 연결은 노드 내용을 먼저 저장한 뒤 나중에 편집할 수 있습니다.

관계 해석 목록은 관계명을 왼쪽, 계열 표시를 오른쪽에 배치한 한 줄 선택 항목으로 구성합니다. 선택 상태는 옅은 배경과 체크 표시로 구분하고, 긴 관계명은 줄바꿈합니다.

07

캔버스 맥락으로 글쓰기

캔버스 전체의 이미지 해석·연결 방향·관계 정의·의견을 글쓰기 가이드로 정리합니다. 가이드 생성은 온톨로지 자동 추론이나 AI 글 생성과 구분합니다.

글을 작성할 AI 설정

제공자·API 키·모델을 설정합니다. 실제 API 키는 이 예시에서 입력받지 않습니다.

API 설정은 개인 브라우저에 보관하며 협업 데이터와 작업 백업에 포함하지 않습니다.

글의 재료와 작성 방향

선택한 일부 항목이 아닌 캔버스 전체 네트워크를 읽습니다. 목적·독자·형식·관점과 서술 순서를 정한 뒤 가이드를 저장하고 AI에게 글쓰기를 요청합니다.

글쓰기 결과물

API 세팅 탭에서 AI 설정을 먼저 완료해 주세요.

명시적으로 요청할 때만 생성합니다. 요청 실패·취소 시 이전 결과를 유지하며 복사와 TXT 다운로드를 제공합니다.

오른쪽 슬라이드는 데스크톱 75vw, 800px 이하에서 전체 너비입니다. 캔버스 화면을 왼쪽으로 밀되 노드 좌표는 유지합니다. 닫기 버튼으로 종료하고, 자료가 바뀌면 가이드를 다시 저장합니다.

08

실제로 쌓이는 지식의 구조

물리 기반 배치

복수·양방향 관계는 곡률을 나눠 겹침을 줄입니다. 배치를 멈추거나 다시 시작할 수 있으며, 동작 줄이기 설정에서는 초기 배치 후 정지합니다.

표준과 검증을 구분

RDF/OWL 어휘와 SHACL 제약을 보여줍니다. JSON-LD 내보내기는 관리자에게만 활성화하며 실행 시 온라인 인증을 확인합니다. 제약을 보여주는 것만으로 데이터 검증이나 자동 추론이 완료됐다고 표시하지 않습니다.

서술 순서는 자료 제시 순서이며 연결 방향과 구분합니다. AI 입력은 정의 화면과 같은 온톨로지 어휘와 저장된 캔버스의 구조화된 네트워크를 함께 사용합니다. 지식 구조는 가이드·자료 사본·실제 AI 입력·생성 결과를 구분하고, 기록이 없는 출처는 추정하지 않습니다. 온톨로지도 글쓰기와 같은 슬라이드로 엽니다. 보기 드롭다운을 사용하고 닫기 버튼으로 돌아오며, 시각화 배치는 원본 캔버스를 바꾸지 않습니다.

09

개인의 설정과 함께 쓰는 맥락

로그인·협업

로그인 전에는 로그인 슬라이드를 열고 닫기를 비활성화합니다. 로그인 후 캔버스를 사용하며 공유 공간에서는 참여자·초대·동기화 상태를 안내합니다.

새 캔버스

노드가 있는 캔버스만 왼쪽에 날짜·시각 칩으로 보관합니다. 빈 캔버스는 중복 생성하지 않습니다. 개인 목록은 계정별로 현재 브라우저에 저장됩니다.

작업 백업·복원

계정 및 작업 관리 슬라이드의 별도 탭으로 제공합니다. 이미지·관계·의견·가이드·결과를 보관하며 복원 전 현재 작업을 백업합니다. API 설정은 제외합니다.

다른 작성자의 노드는 읽기 전용으로 표시합니다. 협업에서는 서버에서도 작성자 권한을 검사합니다. 동기화 충돌 시 입력을 보존하고 상태와 다음 행동을 안내합니다.

캔버스 목록과 작업 영역

로그인 후 빈 캔버스 중앙에는 이미지 드래그 안내를 표시합니다. 노드가 있거나 로그인 전이면 숨기고, 안내는 드롭·드래그·클릭을 가로채지 않습니다.

데스크톱에서는 내 캔버스 목록을 왼쪽에 배치합니다. 목록 아래까지 이어지는 영역은 공통 색상 토큰의 쿨화이트 배경과 얇은 오른쪽 경계선으로 캔버스와 구분합니다. 800px 이하에서는 목록을 캔버스 위의 가로 스크롤 행으로 표시합니다. 저장된 캔버스를 열면 실제 작업 영역에 맞춰 노드가 보이도록 화면을 보정합니다.

계정·관리 화면의 구성과 상태

도네이션은 새 캔버스 앞에 보조 버튼으로 배치합니다. 후원 안내는 최대 600px의 모달로 열고 닫기 버튼으로 종료합니다. 배경 클릭과 Esc로 닫히지 않으며 포커스는 모달 안에 유지하고 종료 후 진입 버튼으로 돌려줍니다. 공통 색상·제목 서체·44px 버튼 높이를 사용합니다.

상단 진입 버튼과 슬라이드 제목은 계정 및 작업 관리로 통일합니다. 로그인·협업, 작업 백업·복원 순서로 탭을 배치하고 관리자는 사용자 관리, 콘텐츠 관리를 추가로 봅니다. 로그인 전에는 닫기 버튼을 비활성화합니다.

계정과 로그아웃

로그인한 계정 라벨과 이메일, 테두리가 있는 로그아웃 버튼을 하나의 카드로 묶습니다. 버튼은 최소 높이 44px, 카드 안 여백은 20px, 요소 간격은 16px입니다.

관리 목록

안내·도구·목록을 같은 중앙 너비에 정렬합니다. 전체 사용자 보기와 목록 새로고침은 하나의 도구 행으로 묶고 12px 간격을 둡니다. 설정 미완료·빈 목록·오류는 별도로 안내합니다. 삭제는 확인 후 실행하고 숨김은 해제할 수 있습니다.

권한 표시

디자인 시스템 링크와 온톨로지 JSON-LD 내보내기는 관리자에게만 활성화합니다. 관리자 탭은 일반 사용자에게 숨깁니다. 문서 본문은 온라인 관리자 인증 후 표시합니다. 정적 파일의 원문 비공개를 보장하는 방식은 아닙니다.

하단에는 저장 상태·배율·노드와 연결 수·© 2025 WORFLOGY Inc. All rights reserved.를 표시합니다. 작은 화면에서는 저작권을 다음 행으로 옮깁니다. API 설정은 서버 저장·공유·파일 백업 대상에서 제외합니다.

작성자 표시

기본 작성자 이름은 로그인 ID(이메일)입니다. 새 캔버스에도 로그인 ID를 사용합니다. 사용자가 설정한 이름과 기존 기록은 유지합니다. 본인이 작성한 노드·관계 해석·의견에는 화면에서만 (나)를 덧붙이고 다른 참여자에게는 저장된 이름을 표시합니다. 본인 여부와 수정·삭제 권한은 이름이 아닌 소유자 ID로 구분합니다. 생성자를 확인할 수 없는 기존 기록에는 (나)를 붙이지 않습니다.

화면 언어

언어 전환은 상단의 두 버튼으로 제공합니다. 선택 상태는 색상과 aria-pressed로 표시합니다. 화면 문구와 접근성 라벨만 번역하며 사용자 데이터와 선택 값은 유지합니다. 영어의 긴 문구는 줄바꿈하고 모바일 가로 넘침을 방지합니다.

저장된 관계 해석 관리

저장된 관계 해석은 관계명 아래의 해석 수정·해석 삭제 버튼으로 관리합니다. 작성자만 변경할 수 있습니다. 수정 시 기존 의견과 동의·비토는 유지하며, 삭제 시 해당 해석의 의견과 반응도 함께 삭제합니다. 연결선과 다른 해석은 유지됩니다.

연결 방향 바꾸기

연결을 선택하면 출발 이미지와 도착 이미지가 표시됩니다. 연결 작성자는 방향 바꾸기로 화살표를 반대로 바꿀 수 있습니다. 해석과 의견은 그대로 유지되므로 새 방향에 맞는지 확인해야 합니다. 협업에서는 DB의 방향 변경 업데이트가 적용되어 있어야 합니다.
